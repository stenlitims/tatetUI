Достатньо передати агенту адресу цього сайту. Усе для вибору та перенесення
компонентів доступне через звичайні HTTP-запити, без клонування репозиторію,
авторизації чи запуску JavaScript у браузері.

## Швидкий старт

1. Прочитайте [llms.txt](/llms.txt) — точку входу для агентів.
2. Знайдіть потрібні компоненти в [JSON-каталозі](/registry/index.json).
3. Прочитайте документацію та API за полями `markdown` і `api` компонента.
4. Отримайте його `registry` JSON або скачайте ZIP за полем `download`.
5. Перенесіть файли, підключіть CSS і встановіть зовнішні залежності, якщо вони є.

Для читання всієї документації одним запитом є [llms-full.txt](/llms-full.txt).
У Markdown живі демо замінені повним кодом прикладів; посилання на JSON API
дають актуальні props, події, слоти та методи. Описи подій також містяться
в тексті документації та на звичайній сторінці компонента.

## Приклад HTTP-запитів

Замініть `https://your-tatetui-site.example` на адресу відкритого сайту:

```bash
curl -fsSL https://your-tatetui-site.example/llms.txt
curl -fsSL https://your-tatetui-site.example/registry/index.json
curl -fsSL https://your-tatetui-site.example/registry/components/button.json
curl -fsSL https://your-tatetui-site.example/registry/downloads/button.zip -o button.zip
unzip button.zip -d ./tatetui-button
```

Спочатку розпакуйте в окрему папку й порівняйте зі своїм проєктом. Не
перезаписуйте вже адаптовані компоненти або токени без перегляду змін.

## Формат каталогу

[Каталог](/registry/index.json) має `schemaVersion: 1` і масив `components`.
Кожен елемент містить `name`, `component`, `title`, `description`, `status`,
`docs`, `markdown`, `api`, `registry` та `download`. Усі URL у JSON починаються
з `/` — додавайте origin того сайту, з якого отримали каталог.

JSON окремого компонента додатково містить:

| Поле | Призначення |
| --- | --- |
| `files` | Повний набір вихідних файлів, включно з вкладеними залежностями та базовими стилями |
| `files[].path` | Шлях у структурі Nuxt 4, наприклад `app/components/ui/UiButton.vue` |
| `files[].content` | Повний текст файлу — можна зберегти без додаткового запиту |
| `files[].url` | Пряме посилання на той самий вихідний код як текст |
| `files[].sha256` | SHA-256 вмісту для перевірки завантаження |
| `dependencies` | Зовнішні пакети та їхні версії для `bun add` |
| `peerDependencies` | Вимоги до Vue та Tailwind у цільовому проєкті |
| `overrides` | Узгодження версій, потрібне, зокрема, TipTap / ProseMirror |
| `integration` | Додаткові вимоги, наприклад NuxtLink |
| `revision` | SHA-256 набору файлів і залежностей для порівняння версій |

Архів містить ті самі вихідні файли, `registry.json`, README та документацію
компонентів і основ. Залежності визначаються за реальними імпортами рекурсивно
та доповнюються `dependsOn` з документації. Це включає внутрішні компоненти,
утиліти, composables і CSS, які не видно в одному `.vue`-файлі.

## Підключення в Nuxt 4 з Tailwind 4

Збережіть структуру `app/` з архіву. Аліас `~` має вказувати на `app/`.
У наявний CSS-файл, який уже підключено в Nuxt, додайте:

```css
@import 'tailwindcss';
@import './tokens.css';
@import './theme.css';
@import './components.css';
```

Шляхи в прикладі припускають, що CSS-файли лежать разом у `app/assets/css/`.
`components.css` містить базові стилі, утиліти прокрутки й підтримку
`prefers-reduced-motion`. Не додавайте `tailwindcss` вдруге, якщо він уже імпортований.
Tailwind має сканувати скопійовані `.vue` та `.ts` файли; для файлів поза
стандартним деревом джерел додайте `@source` у свій CSS entry point.

Для Prose та RichTextEditor також підключіть `ui-prose.css` з архіву:

```css
@import './ui-prose.css';
```

Встановіть пакети з `dependencies`; для більшості компонентів цей об'єкт
порожній. Для RichTextEditor перенесіть також `overrides` у `package.json`.
Приклад використання та доступний API беріть зі сторінки компонента.

Один раз додайте `viewport-fit=cover` до meta viewport. Тема перемикається
класом `.dark` на `<html>`. Для перекладів підключіть
`setUiTextTranslator()` з `useUiText.ts`; деталі в [інструкції перенесення](/docs/copy-guide).

## Vue / Vite, Nuxt 3 та Tailwind 3

У Nuxt 3 і Vue/Vite змініть корінь файлів під структуру свого проєкту та
налаштуйте `~` на відповідний каталог джерел. У Vue/Vite компоненти імпортуються
явно; Vue API в самих компонентах уже імпортовано.

Якщо `integration` вказує на `#components`, у Vue/Vite замініть імпорт
`NuxtLink` обгорткою над Vue Router `RouterLink`, яка підтримує `to`.
Це потрібно для Button, Breadcrumb, NavigationMenu, PageHeader та StatCard,
а також для компонентів, які використовують їх усередині.

Готовий CSS в архівах орієнтований на Tailwind 4. На Tailwind 3 потрібна
адаптація `theme.css`, `@utility` та варіантів на кшталт `pointer-coarse:`.
Дивіться [Токени](/docs/foundations/tokens) і перевіряйте згенеровані стилі
в цільовому проєкті.

## Перевірка після перенесення

Запустіть перевірку типів і збірку цільового проєкту. Перевірте світлу та
темну теми, клавіатуру, мобільний viewport і потрібні сценарії компонента.
Дотримуйтеся статусу з каталогу: `wip` означає, що API ще змінюється.

Каталог, Markdown, вихідні тексти та ZIP генеруються під час кожної збірки
сайту з того самого коду. Для оновлень порівнюйте `revision` та хеші файлів;
спільні composables оверлеїв мають залишатися в одному екземплярі.
