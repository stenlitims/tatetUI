# tatetUI

Канонічна бібліотека UI-компонентів + сайт документації українською.
Зібрана з найкращих реалізацій у кількох продуктових кодових базах.
Компоненти копіюються в проєкти, а не встановлюються пакетом.

## Команди

```bash
bun run dev          # dev-сервер
bun run build        # збірка + прередер (падає на будь-якій помилці)
bun run typecheck    # типи (збірка їх НЕ перевіряє)
bun run check:docs   # десять перевірок дрейфу документації
```

Пакетний менеджер — **bun**, не npm.

## Правила дому

Кожне правило тут з'явилося тому, що його порушення коштувало реального
бага. Не «стиль», а наслідки.

### Компоненти

**Union оголошуй інлайново в `defineProps`, аліас виводь із нього.**
`nuxt-component-meta` друкує в таблиці API те, що бачить у `defineProps`.
Посилання на аліас дає в колонці «Тип» слово `Variant` замість переліку
значень — тобто саме те, заради чого таблицю відкривають.

```ts
const props = withDefaults(defineProps<{ variant?: 'solid' | 'ghost' }>(), {...})
type Variant = NonNullable<typeof props.variant>   // не навпаки
```

**Кожен компонент оголошує `defineSlots<{}>()` з JSDoc.** Для генеричних
компонентів (`generic="T"`) слоти з шаблону не читаються взагалі
([language-tools#3429](https://github.com/vuejs/language-tools/issues/3429)),
і таблиця лишиться без секції «Слоти».

**JSDoc на кожному публічному props.** Це джерело описів у таблиці API.
Опис живе поруч із кодом, тож перейменувати props, не побачивши його опис
на сусідньому рядку, неможливо. Перевіряє `check:docs`.

**Події описуй у frontmatter, а не JSDoc.** `nuxt-component-meta` не
витягує JSDoc подій за будь-якого синтаксису. Ключі `emitDescriptions`
звіряються з `defineEmits` в обидва боки.

**Іконка — слот, не рядок-клас.** У вихідних проєктах два різні підходи
(Font Awesome і власні SVG-SFC); слот працює з обома і не тягне залежності.

**Стан помилки вмикає наявність тексту, а не булевий прапорець.** Так
неможливо отримати червоне поле без пояснення чому.

**`aria-describedby` вказує рівно на один опис.** Інакше скрінрідер зачитає
інструкцію, яку користувач щойно порушив, раніше за причину відмови.

**`v-if` і `v-for` — на різних вузлах.** У Vue 3 `v-if` має вищий пріоритет
і не бачить змінної циклу.

### Стилі

**Тільки токени, жодних сирих кольорів.** `bg-card`, а не `bg-white
dark:bg-neutral-900`. Компонент має працювати в обох темах без `dark:`.

**`@theme inline` — `inline` обов'язковий.** Без нього утиліта копіює
значення `var()`, і `.dark` перестає діяти.

**Мобільна ціль дотику — 44px, а не видима висота.** Поля на мобільному
фізично `h-12` (45px за кореня 15px) з текстом 16px — інакше iOS Safari
зумує сторінку при фокусі. Кнопки й сегменти зберігають ієрархію
(`h-9`→`md:h-8`, `h-10`→`md:h-9`, `h-12`→`md:h-11`), а точність дотику
тримає невидима зона 45×45 через `pointer-coarse:after:`. Де елемент
мусить лишатися дрібним — невидима зона через `::after`.

**`focus:outline-none` без заміни заборонено.**

**`overflow-clip`, а не `overflow-hidden`, на контейнерах із липкими дітьми.**
`overflow: hidden` створює власну область прокрутки, і `sticky` всередині
(UiActionBar, шапки таблиць) липне до контейнера, а не до екрана — тобто не
липне взагалі. `overflow-clip` обрізає кути так само, але області прокрутки
не створює.

**Два класи з однієї властивості на одному елементі — баг, а не перевизначення.**
`inline-flex` + `flex`, `top-0` + `top-[14%]`, `mb-1` + `mb-0`: переможе той,
що нижче в згенерованому CSS, а не той, що правіше в шаблоні. Варіант
обирається в JS (одна гілка — один клас), а не дописується поверх.

### Залежності

**Бібліотека не має зовнішніх залежностей.** Позиціонування, пастка фокуса,
блокування прокрутки — усе своє. Компонент має копіюватись у чужий проєкт
без `bun add`.

**`import.meta.client` не використовуй** — це специфіка Nuxt. Перевіряй
`typeof document !== 'undefined'`: бібліотеку копіюють і у Vite-проєкти.

### Документація

**Демо живуть в `app/demos/`, поза `app/components/`.** Інакше вони
засмічують автоімпорт. Basename має бути глобально унікальним — реєстр
ключується саме ним.

**Глоби демо — НЕ `eager`.** З `eager: true` усі демо потрапляють у
entry-чанк і їдуть на кожну сторінку сайту.

**Сторінка компонента має обов'язковий набір розділів** (`## API`,
`## Коли використовувати`, `## Коли НЕ використовувати`). Перевіряє
`check:docs`.

**Хром сайту будується з самої бібліотеки.** Мобільна навігація — реальний
`UiDrawer`, пошук — реальний `UiModal`. Якщо власну документацію незручно
збирати зі своїх же компонентів — з бібліотекою щось не так.

**Клас `docs-prose` — на самому `ContentRenderer`, не на обгортці.**
`ContentRenderer` рендерить власний кореневий `<div>`. Обгортка навколо нього
додає рівень вкладеності, і `.docs-prose > * + *` — єдине правило, що дає
вертикальний ритм між блоками, — перестає збігатися з будь-чим. Сторінки при
цьому виглядають майже нормально, бо ритм тримають заголовки з власними
марджинами; помітно стає аж там, де підряд ідуть абзаци й блоки коду.
Перевіряє `check:docs`.

**Правило CSS, яке не спрацювало, виглядає точно як правило, якого немає.**
Коментар, що втратив свій `/*`, стає селектором аж до наступної `{` — і разом
із ним мовчки гине ціле правило. Так загинуло `.docs-prose { line-height: 1.7 }`
і виявилося лише вимірюванням computed-стилю. Тому стилі перевіряються
`getComputedStyle` у браузері, а не читанням файлу. `check:docs` ловить
непарні межі коментарів і кирилицю в селекторі.

## Архітектурні рішення

**Прередер + `useAsyncData` зі стабільним ключем** — це те, що тримає
WASM-SQLite (864 КБ) поза клієнтським бандлом. `ssr: false` вмикати не можна.

**Підсвітка коду робиться в Node на етапі збірки** через Vite-плагін
`?raw&shiki`. Бібліотека Shiki у клієнт не потрапляє взагалі.

**Один overlay-стек на всі оверлеї.** `useOverlayStack`, `useScrollLock`,
`useFocusTrap`, `useReducedMotion` спільні для `UiModal`, `UiDrawer`,
`UiConfirmDialog`. Саме через це вкладені оверлеї працюють правильно.

## Відоме обмеження перевірки

`<Transition>` у Vue просуває фази через `requestAnimationFrame`. У
невидимій вкладці (`document.hidden`) rAF не спрацьовує, і вузол назавжди
лишається з класами `enter-from` + `leave-active` одночасно. Це артефакт
середовища, не компонента: логіка (стек шарів, лічильник блокування,
очищення черги) при цьому відпрацьовує коректно.
